# 输出 Schema：script.md / beat-sheet.md

两份文件都是给下游 Agent（而不是程序）读的，所以用 Markdown 而不是 JSON；但字段顺序与标题
必须固定，方便下游用简单的正则/小模型解析，不需要每次重新理解自由格式。

## `script.md`

```markdown
# 脚本：<视频标题或链接>

- 来源链接：<url>
- 总时长：<Xs>
- 是否含语音/字幕：是/否

## 镜头 001（0.0s–2.4s）
- 画面：<画面内容描述，包含主体、动作、构图>
- 镜头运动：固定 / 推 / 拉 / 摇 / 跟随 / 手持晃动
- 转场（进入本镜头的方式）：硬切 / 叠化 / 擦除 / 匹配剪辑 / 片头
- 字幕/口播：<原文，若无则写"无">

## 镜头 002（2.4s–5.1s）
...
```

每个镜头一个二级标题，标题里带时间区间，方便下游直接按时间轴对齐。镜头编号与
`shots.json` 里的 `frame` 文件名一一对应（`shot-001.jpg` ↔ `镜头 001`）。

## `beat-sheet.md`

```markdown
# 高光节点时间轴：<视频标题或链接>

| 节点 | 时间 | 内容概述 | 为什么有效 |
|---|---|---|---|
| 钩子 | 0.0s–2.4s | <一句话> | <这个开场为什么能留住观众> |
| 痛点 | 2.4s–6.0s | <一句话> | <为什么这个痛点戳中目标用户> |
| 卖点展示 | 6.0s–14.0s | <一句话> | <展示方式为什么有说服力> |
| 转折 | 14.0s–17.0s | <一句话> | <转折制造了什么情绪落差> |
| 行动号召 | 17.0s–20.0s | <一句话> | <CTA 为什么放在这个时机> |

## 节奏观察
- 平均镜头时长：<Xs>，卖点展示段落是否明显更快/更慢
- 全片是否有一个反复出现的视觉锚点（同一构图/同一物体）
- BGM 情绪转折点是否与画面节点对齐（若可判断）
```

节点行数不固定——一条视频可能没有明显的"转折"，也可能有两次"卖点展示"。表头五列
（节点 / 时间 / 内容概述 / 为什么有效）是硬约束，"节点"取值不设枚举，按实际结构命名。

**"为什么有效"这一列是整份文档存在的理由。** 下游改写时复用的是这一列描述的机制
（比如"3 秒内用反差画面制造疑问"），而不是这一行的具体文字内容。
