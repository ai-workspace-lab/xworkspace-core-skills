# 云原生十二要素的开发适用范围

以 [The Twelve-Factor App](https://12factor.net/) 为来源，按当前技术栈采用以下做法。

| 要素 | 开发约定与适用条件 |
| --- | --- |
| 1. 代码库 | 每个可发布组件可追溯到版本化源码。单仓与多仓均可，环境差异通过声明表达。 |
| 2. 依赖 | 显式声明应用、运行时、CLI 和 Provider 等依赖，沿用 lockfile、Go modules 与固定版本策略。 |
| 3. 配置 | 将环境差异与代码分离。可通过环境变量或挂载配置注入，秘密沿用受控注入。Next.js 明确哪些值属于公开构建输入，哪些属于服务端运行配置。 |
| 4. 后端服务 | 数据库、缓存和队列经配置连接，保留版本、能力和数据迁移约束。 |
| 5. 构建、发布、运行 | 构建产生可追溯制品，发布绑定制品与部署配置，运行消费已选版本。静态站点的公开构建输入随制品记录。 |
| 6. 进程 | Web/API 副本将持久业务状态和跨副本会话放到明确的存储。进程内缓存可丢弃。数据库等有状态组件单独管理持久化。 |
| 7. 端口绑定 | 常驻 HTTP 服务监听平台指定地址与端口。静态站点、短时命令和托管函数采用各自入口。 |
| 8. 并发 | 按 Web、worker 等角色独立安排容量。结合 PostgreSQL 连接池、队列和外部配额限制并发。 |
| 9. 易处置 | 支持有界启动、优雅退出和安全重启，正确释放连接并处理未完成任务。 |
| 10. 开发与生产一致 | 测试关键依赖的版本与行为，关注 PostgreSQL 事务、缓存和执行目标。环境规模、凭据与资源隔离按用途配置。 |
| 11. 日志 | 应用将日志作为可采集事件输出，保留请求关联和结果，按要求脱敏。审计事件按实际治理规范保存。 |
| 12. 管理进程 | 迁移、回填和批任务走显式一次性入口，记录目标、版本、执行身份及结果。权限与生产执行沿用运维规范。 |

构建和流水线交付参见 [CI/CD 工程规范](../../../engineering-standards/ci-cd-workflow-spec/SKILL.md)。运行、日志及审计参见[服务目录和 Runbook](../../../operations-management/service-catalog-and-runbook-standard/SKILL.md)。
