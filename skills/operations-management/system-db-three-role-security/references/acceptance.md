# 三权分立：最小增量交付与验收

## 分阶段，而非全量重做

| 阶段 | 最小变更 | 前置与退出条件 |
|---|---|---|
| 0 只读基线 | 列出系统/容器/数据库实际身份与越权入口 | 脱敏事实、消费者、版本、影响与未验证项齐全；不改生产 |
| 1 收敛暴露 | 修正已确认的管理凭据可读性及其持久生成源 | 管理入口仍可用；普通身份实际不能读管理秘密；不顺带轮换或改业务身份 |
| 2 建立审计 | 建独立系统/集群/DB 审计身份及最小读取路径 | 先 UAT 验证允许/拒绝；应用仍用原身份；只迁移巡检调用方 |
| 3 单服务业务降权 | 为一个服务建立必需 DML、目录和运行身份 | 连接池/序列/默认权限/任务回归通过，灰度切换，有前一版本恢复办法 |
| 4 单服务 rootless | 校验镜像、UID/GID、卷、端口和 capabilities | 实际进程非 root，业务 E2E 与重启/恢复通过；不清空已有卷 |
| 5 收尾 | 确认无消费者依赖旧权限后逐项撤除 | 观察、拒绝测试、审计证据和旧权限退出记录齐全 |

阶段可按实际问题缩小或合并，但不能跳过身份验证、业务证据或回退依据。遇到阻断保持上一阶段服务，不把失败伪装为成功；是否回退取决于数据是否已经产生新的写入。

## 三类身份必须覆盖的断言

| 层面 | 允许 | 必须拒绝或明确隔离 |
|---|---|---|
| 管理用户 | 受授权管理操作、查看管理状态 | 不作为应用进程/连接池的日常身份；管理凭据不挂进业务 |
| Linux 业务 | 必需目录、端口与独立服务运行 | 通用 sudo、管理 kubeconfig、runtime socket、其他服务秘密 |
| Linux 审计 | 状态/指标/授权脱敏日志与受控输出目录 | 系统/业务文件变更、管理秘密读取、提权与任意特权执行 |
| K3s 业务 | 必需 ServiceAccount、命名空间内有限能力；实际 UID/GID 非 root | cluster-admin、privileged、非必需 hostPath/capabilities/宿主机 namespace |
| K3s 审计 | 授权状态、事件和指标读取 | Secrets、exec/attach/proxy、令牌、写入和 RBAC 修改；原始 ConfigMap/日志按敏感性另审 |
| DB 业务 | 目标业务对象 DML、必需序列 | 管理/复制/绕过 RLS/服务器执行能力；不因 ORM 迁移需要永久保留 DDL 管理权 |
| DB 审计 | 指定监控与脱敏视图；约束后的查询 | INSERT/UPDATE/DELETE/TRUNCATE/DDL、角色提升、秘密列、可写函数；TEMP 按范围收敛 |

只读权限自省需包含对象所有者、继承/SET ROLE、PUBLIC/default ACL、函数执行和 K8s 聚合角色。只验证用户名称、默认 READ ONLY 或一次 SELECT 成功均不足。

## 证据分级

- 配置证据：身份、RBAC/ACL/模式已声明；不等于有效授权已正确落地。
- 登录证据：真实目标身份可以认证；不等于它不能越权。
- 运行证据：允许和拒绝均验证，业务运行身份及受控恢复回归完成，才可评为对应阶段 PASS。
- 当前检查仍以 root/DB 管理员执行时，报告应写“只读执行纪律”，不能写“审计身份权限隔离通过”。

Markdown 供人和 AI 阅读；JSON/回执供门禁；JUnit 中必需项目 PARTIAL、NOT_RUN、UNKNOWN、SKIPPED 都不能视为通过。保留最小非敏感事实，不保存 token、私钥、DSN 或秘密原值。

## 场景边界检查

1. 只要求检查：只读盘点和差距报告，不自动开户、改权限或重启。
2. 管理 kubeconfig 世界可读：核对父目录/ACL和实际读取，再计划最小修正及持久源修复；不以新增无 sudo 用户宣称隔离。
3. 业务 DB 超级用户：先盘点必需 DML/迁移消费者，按一个服务灰度降权，不整库迁移、不一并重建。
4. 想让审计查看所有原始数据：区分状态可见和秘密可见，用脱敏视图/接口满足任务，不能授予全库读取后称其无风险。
5. Pod runAsNonRoot 但挂 runtime socket/privileged：仍未通过业务权限边界；不能凭 UID 配置给 rootless PASS。
6. 用户只批准最小渐进改造：每个增量单独列范围、可用性、验证和恢复；不能借安全规范扩大为全面迁移。
