# Unified GitOps 运行与验收

按[多执行器治理](../../../engineering-standards/execution-ownership-migration/references/unified-gitops.md)确定目标、声明和写入边界。服务目录引用 GitOps 路径、环境、执行 owner、目标标识、触发方式、健康信号和回退入口。

## 渐进接管

1. 只读盘点现有声明、定时器、CI、手工入口、管理身份和实际写者。核对数据卷、网络、秘密及依赖，记录当前应用版本、健康基线和恢复点。
2. 用隔离环境或低风险单元验证目标执行器对同一资源的身份、应用、漂移及回退行为。涉及删除或替换时，先核对 Compose/Swarm 删除策略、Flux prune 和持久数据生命周期。
3. 在已授权窗口内逐单元停用旧写入路径，再启用新执行器。验证实际接管后再扩大范围。接管失败时先暂停新写入，按已验证的边界恢复旧执行路径，避免同时写入。涉及数据库迁移、数据写者交接或不可逆变更时，按[备份与恢复规范](../../backup-disaster-recovery-and-data-migration/SKILL.md)核对数据兼容性和恢复点。
4. 按[系统与数据库三权分立](../../system-db-three-role-security/SKILL.md)分离系统管理、业务运行和强制只读审计身份。Docker API 写权限按高权限管理，业务及审计身份无部署器套接字权限。业务逐步采用独立非 root 身份，部署器权限按环境和目标收敛。

## 验收与观测

| 执行器 | 变更与漂移证据 | 运行证据 |
| --- | --- | --- |
| Ansible Pull | 定时触发、互斥、实际 revision、任务结果。对支持幂等的任务，重复运行并验证受管配置能从隔离漂移样本恢复。 | 检查生效文件及服务状态。涉及 SSH 或防火墙时，验证独立连接及回退路径。 |
| Doco CD | 关联轮询或 Webhook、部署结果、实际 revision 和目标项目。用隔离样本验证无新提交时的漂移检测及恢复入口。 | 检查实际镜像、容器健康或 Swarm 服务副本、应用探测及有状态服务的必要读写。 |
| Flux CD | 核对源 revision、资源对应的 observedGeneration、调谐结果和依赖状态。按实际配置验证漂移修复、告警及删除语义。 | 检查 rollout、工作负载就绪、应用探测及必要业务路径。 |

把触发接收、变更应用、漂移处理和服务健康分别记录为可核对的结果。记录环境、目标、提交、制品、执行身份用途、run ID 或事件引用、时间、结果及脱敏证据。失败、跳过和未验证分别标记。采集最近成功时间、连续失败与漂移信号，关联应用指标、日志和告警。[统一可观测性架构](../../unified-observability-architecture/SKILL.md)

## 回退与应急

回退入口引用已验证的 Git revision、制品和运行前提，按同一 owner 重新应用并复验。回退涉及数据时，按兼容性和恢复点选择恢复路径。紧急手工修复按[故障与变更管理](../../incident-response-and-change-management/SKILL.md)记录临时写者、暂停范围和恢复条件。恢复自动调谐前，将需要保留的变更回写 Git，确认执行器的实际目标版本与声明一致。
