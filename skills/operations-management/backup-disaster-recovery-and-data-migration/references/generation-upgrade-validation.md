# 代际升级的运维验收与历史回归

适用于源继续服务、候选隔离准备的代际替换。阶段及放行规则以[可重复升级验收](../../../engineering-standards/generation-upgrade-acceptance/SKILL.md)为准；本参考拥有数据保护、恢复、回归和切换证据细则。按实际数据库、采集栈、业务模型适配，不默认某云平台、域名、迁移 CLI 或商业产品。

## 运行参数与候选身份

使用工程验收技能的参数契约选择 provider/environment、源/目标代际及 manual/pipeline 执行路径；两种模式使用相同数据和业务边界，不因使用 SSH、某流水线或 CD 产品改变保护规则。

每次执行回执绑定归一化参数、实际资源身份、固定执行器/控制器版本、run_id/attempt_id、各仓库 main 合并 commit、不可变 tag、实际构件 digest 和声明 commit。全新部署、恢复、迁移、case 和观察记录必须能关联到同一候选；平台、环境、代际或路由参数变化后先重验目标身份和隔离条件，不能复用原目标的通过结论。

## 目标保护与数据一致性

1. 修改现有目标前完成独立、可解密、可校验的备份和隔离恢复。全新空库恢复只证明操作机制；核心数据对齐后再备份恢复含业务数据的候选。保护现有演练及回退构件，清理另按授权执行。
2. 源使用最小权限的一致性只读快照，记录时间/日志位置等边界；源继续写入时允许差异增长，最终切换必须再追齐。数据快照、测试夹具与真实流量分别标明。
3. 合并计划绑定源/目标身份、快照、目标基线、工具版本、schema、迁移记录及内容摘要；应用前重新检查，过期或冲突即停。暂停目标独立写入，通过锁/事务等数据库能力保证计划应用的原子性。
4. 相同不可变事实重放应为空操作，同键不同内容即冲突。保护身份、认证凭据及目标独有事实；配额/余额等可变状态不能按整行覆盖独立目标活动，须有审核过的合并规则。
5. 核对业务指纹和结构指纹，迁移元数据与预期新增对象单独审核。SQL 文件校验和不等于数据库结构哈希；计数相同不等于内容一致。核对应用实际连接库、权限、迁移 version/dirty 或同等状态。
6. 恢复到独立库/目标，验证应用连接、代表性查询和业务不变量，不激活生产任务或真实支付/通知。记录备份来源、校验和、恢复位置、耗时、实际 RPO/RTO 和失败点。

## 历史问题真实回归

从当前事件记录、已部署配置和本轮变更确定适用项。以下 case_id 只是逻辑风险类别，不代表脚本已经存在。把问题引用解析到所属仓库的实际脚本，缺失则补实现或标阻断。新增功能增加相应用例，禁止只复制往次 PASS。

| 风险类别 | 实际验证要求 |
| --- | --- |
| 证书与公共 SNI | 在不改公共 DNS 的条件下，将公共 Host/SNI 指向候选；验证信任链、SAN、有效期、证书挂载和路由，不跳过校验。 |
| 域名清单遗漏 | 从权威声明枚举业务、根域、别名、重定向及边缘绑定；核对路径、查询参数和正确页面/API，不能只检查控制台。 |
| 密钥未注入进程 | 核对声明引用与容器/进程实际配置；只输出一致/缺失，不输出凭据值或散列。 |
| 健康正常但业务入口阻断 | 验证真实写入接口的路由和授权成功/失败路径；隔离样本处理及重复投递结果正确，管理端点仍受保护。 |
| 候选角色残留到正式运行 | 按工程技能的身份边界核验进程实际连接角色；隔离验证注册所需写入、账务/流量持久化和序列访问，确认审计读取角色写入被拒绝。覆盖只读事务、仅写会话、后台写入关闭及入口拦截；重跑部署/恢复不得把正式配置改回候选配置。角色/配置检查与真实业务 case 分别记录。 |
| 采集链路中断 | 从隔离采集器、转发器到候选写入及查询边界验证新鲜度、预期样本和持久化结果；不得双投生产记账。 |
| 注册/客户端不可用 | 隔离节点或身份验证注册、心跳、配置下发、协议/路径和实际连接；无条件测试则标阻断，不能擅自移动生产节点。 |
| 认证与外部回调错路由 | 验证候选认证、会话、OAuth/Webhook。客户端指定解析不能证明外部提供方回调通过；使用授权隔离入口并记录覆盖缺口。 |
| 数据覆盖/冲突 | 在夹具验证身份歧义、同键不同内容、可变额度及目标独有事实，冲突原子回滚；运行核验实际同步范围。 |
| 迁移/部署重复和中断 | 真实测试并发锁、错误校验和拒绝、重试幂等、中断及目标服务重启；无重复写入、配置漂移和不必要重启。 |
| 部署恢复配置分叉 | 全新部署、原地重跑和隔离恢复使用相同证书、密钥、路由、卷及权限维护源；恢复不得重新引入旧测试配置。 |
| 切换后旧源写入遗漏 | 检查工具真实能力；在夹具验证基线、新增/缺失/冲突检测、单对象预览及幂等补同步，不覆盖当前目标状态。 |

每项回执保存 run_id、候选及脚本 commit、case_id、问题引用、具体命令或脚本、预期、带时区起止、退出码、PASS/FAIL/BLOCKED/NOT_RUN 和脱敏证据位置。没有真实执行不能填 PASS；不适用项记录理由，不能用于绕过必测项。

## 故障修复后的运行关闭

遵循工程验收技能的修复 → PR → main → 新不可变 tag/构件 → 固定声明 → 重新部署 → 重新验收闭环，运维侧补齐以下证据：

- 失败轮次的快照边界、目标状态、错误、受保护数据和回退点保留，后续重跑不得先清库或恢复旧快照来消除差异。
- case 关联原问题、修复 PR/main commit、新候选与重新运行结果。只有修复代码合并或脚本静态通过，不关闭运行问题。
- 修复改变数据计划、schema、迁移或依赖关系时，使旧计划/预览失效；核实最新目标备份仍覆盖当前状态，再生成新一致性预览和审核计划。恢复演练及业务指纹按影响范围重做。
- 部署/恢复维护源改变时，验证全新部署和恢复都不会重新引入故障；同版本重跑、重试和观察的回执绑定修复后的候选。
- 全部相关必测 case 与稳定观察通过后才标记问题关闭或候选待切换；失败则继续修复循环。源继续服务，最终冻结/追齐/切换仍按明确授权独立放行。

## 切换和遗漏修复

- 具体切换须明确授权。冻结所有源写入路径，排空在途事务，最终一致性追齐和校验后捕获基线，确认旧写入持续隔离，再开放目标写入并切流量。API、调度、消费者、采集、Webhook、管理员和直连脚本均在范围内。
- DNS 缓存及长连接窗口中，旧入口应拒绝写入或转发当前权威目标；不能以低 TTL 证明单写入者。Webhook 未持久化不得返回成功，重试和事件去重须有业务证据。
- 切换后审计旧源和当前目标。检测新增/遗漏不只依赖 created_at；结合切换基线、稳定身份键及唯一约束，发现旧源写入应定位隔离异常。
- 单对象补同步默认预览，确认范围与计划后事务执行；已存在相同对象为空操作，身份/认证/财务冲突即停。关联对象按工具审核过的真实能力处理，不能宣称全业务通用复制。
- 目标接受写入后，旧源不再是可直接启写的回退库。回退应用需要验证 schema 兼容，数据库反向协调或恢复另作明确决策，不自动降级或覆盖新事务。
- 新目标真实业务稳定验收完成后，才登记为下一轮来源；旧资源清理和删除需要独立范围及授权。
