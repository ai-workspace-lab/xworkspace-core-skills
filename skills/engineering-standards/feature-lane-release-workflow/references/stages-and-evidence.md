# 阶段与证据契约

阶段顺序由所选模型决定；下表是条件清单，不强制 UAT 早于合并。`postmerge-uat` 在 SIT/组合验证及合并后部署独立 UAT；`premerge-uat` 按用户选择先冻结 UAT 再合并。

| 阶段 | 放行条件 | 失败或变化时 |
| --- | --- | --- |
| 定义功能 | owner、发布模型、必需/可选 PR、目标分支、SIT/UAT namespace与生命周期、范围和执行授权明确 | 缺必要输入时先完成可独立的发现 |
| 构建候选 | 各仓 SHA、不可变构件、完整清单和内容指纹一致 | 构建不齐不得伪称可部署 |
| 部署泳道 | 目标身份、域名、资源配额、隔离数据、实际运行 digest 符合声明 | 不静默回落基线掩盖故障 |
| SIT | 契约、集成、schema 兼容及适用历史回归通过 | 修复产生新候选并重验 |
| UAT | 本模型对应的完整候选冻结，真实业务流程、登录与页面/数据对账通过 | 新提交不自动替换活跃 UAT |
| 组合验证 | 固定 PR 集合与当前目标分支组合，相关检查/审查通过 | 最新目标基线变化后评估并重跑受影响项 |
| 合并 | 有授权、现行 required review/check 通过，跨仓库顺序与兼容窗口明确 | 部分合并保持环境，修复/回退按新变更进行 |
| 合并后复核 | 真实 merge SHA/构件已核对，新构件完成对应回归 | 旧候选证据不覆盖新构件 |
| 回收 | 功能完成或授权取消，证据归档、资源归属和保留规则明确 | 部分失败标待清理并可重试 |

每阶段回执：feature ID、revision、内容指纹、run ID、起止时间与时区、目标、实际版本、脚本/配置 SHA、case、预期、结果、退出码、证据位置、批准例外及失效原因。秘密和个人原始数据不进入回执。

选择测试范围以真实依赖为依据：前端改动检查会话、资源与 API；账户/计费检查认证、幂等、数据链路和业务对账；共享部署/恢复逻辑改动补全新部署、重复收敛和隔离恢复。只做健康探测不能宣称业务通过。

涉及新旧版本并存时覆盖数据库、API、消息和会话兼容。测试低流量场景优先定向人群与确定性自动化；金丝雀观察预算应包含所需业务周期和样本，条件不足标未完成。

动态地址不得作为资源身份：以 provider/account、资源 ID 和当前 CMDB/云 API 事实解析连接地址，核对集群/主机身份；旧 IP、hostname 相同或历史截图不能替代。资源不存在或声明冲突时阻断依赖它的远程操作，不自行重建。IaC 就绪、Flux Ready 和业务验收分别记录；合并后复验不能追认未执行的合并前阶段。
